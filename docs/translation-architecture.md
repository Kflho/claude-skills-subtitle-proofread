# 翻译链路架构与评测（2026-10）

> 目标：把“日文 CC/修复后的日文字幕 → 中文成片字幕”做成一条**可测、可回退**的链路，
> 不是再堆一个 prompt。先调研再写，写完必须用日语参考字幕 + 现有中文字幕做对照。

## 1. 调研结论（为什么这样设计）

| 证据 | 结论 | 对设计的约束 |
|---|---|---|
| SMART / Breaking Babel（arXiv:2609.38660）：长片字幕需要跨集话语/文化上下文、术语与风格一致；用 series-level memory、术语校验、字幕约束校验、judge-refiner | 句子级翻译不够；需要**系列记忆 + 术语校验 + 约束校验 + 只对问题条 refine** | 不要一次翻完整集；批内给上下文；术语表贯穿；QA 后再修 |
| IWSLT 2026 Subtitling Track（aclanthology.org/2026.iwslt-1.10）：字幕系统普遍做**长度/压缩约束** | 长度不是“尽量”，要可检查 | 输出必须有 max chars / CPS 检查 |
| gpt-subtrans / llm-subtrans：按 scene/context 构造 prompt，批处理 + 上下文 + 术语 | 上下文窗口和批次是核心参数 | 批大小、前后文、场景边界要显式化 |
| 任务书 §5.4：LLM 主路径、glossary、前后 2–3 条上下文、角色语气、行长/CPS、两遍法 | 与上述一致 | 作为本项目的最低要求 |

**不采用**：一次整集一个 prompt（上下文爆、错误难定位）；纯规则预替换当主路径
（只补专名，不解决语气/语流）；无 QA 直接写盘。

## 2. 目标链路

```text
源字幕（日语 CC 或修复后的日文 SRT）
  + glossary（ja→zh，系列级）
  + series memory（角色名/固定译法/已确认术语）
        │
        ▼
场景/批次构造：每批 N 条 + 前 3 条 + 后 2 条上下文 + 场景/角色提示
        │
        ▼
LLM 翻译（JSON 数组；system prompt 带 glossary + 长度约束 + 禁止增删）
        │
        ▼
QA（每条）：
  - 日语残留（假名比例）
  - 回显/编号/未翻译
  - glossary 命中（源文出现术语 → 译文必须用指定译名）
  - 行长 / CPS
  - 数字/专名保留
        │
        ├─ 通过 → 写盘
        └─ 不通过 → 只对问题条二次调用（shorten/retranslate）
                          │
                          ▼
                 QA 报告 + 输出 SRT
```

## 3. 与现有 `translate_srt.py` 的关系

现有能力（保留）：

- 批处理（BATCH_SIZE）、前 3 条日文上下文、glossary 注入、OP/ED 预替换、
  专名预替换、失败重试、回显/未翻译检测（`bad_ratio`）、并行 batch。

缺口（本次要补，按优先级）：

1. **硬约束**：max chars / CPS 只写在 prompt 里，没有程序检查；
2. **QA 报告**：没有逐条指标，无法比较“改进前后”；
3. **只修问题条**：失败整批重试，成本高、可能把好条改坏；
4. **未来上下文/场景**：只有前 3 条，没有后文/场景边界；
5. **系列记忆**：glossary 有，但跨集固定译法/角色语气没有持久化；
6. **端到端阶段**：`run_all` 只有“参考字幕→日文”的 step，没有“正片→中文”的正式阶段。

## 4. 评测方案（必须做，且用日语参考）

### 4.1 数据

- **源**：日语 CC（`S01E01–03`，已清洁）；翻译输入直接用它，隔离 ASR 误差。
- **对照**：现有中文字幕（01–05 `sc.ass`/`tc.ass`）——**不是金标**，只做“是否明显跑偏”的 guardrail。
- **样本**：EP001 前 30 条 + EP002/003 各 20 条；全量只在通过后跑。

### 4.2 指标

| 指标 | 定义 | 用途 |
|---|---|---|
| 覆盖率 | 输出条数 / 输入条数；空译文数 | 必须 100% |
| 日语残留率 | 含假名的译条 / 总条数 | 必须 0（歌词/拟声词除外，白名单） |
| 术语命中率 | 源文出现 glossary 术语时，译文含指定译名的比例 | 目标 ≥95% |
| 行长/CPS 违规率 | 超过 max_chars 或 max_cps 的条数占比 | 目标下降 ≥50% |
| 回显/编号率 | 译文含“1.”、原文照抄、未翻译 | 目标 0 |
| chrF vs 中文对照 | 字符 n-gram F 值 | 只作 guardrail：新链路不得显著低于 baseline（±1.0） |
| 抽检 MQM（10 条） | 准确/流畅/术语/风格/长度 5 维 1–5 分 | 新链路必须不低于 baseline |

### 4.3 实验设计（ablation）

1. **baseline**：现有 `translate_srt.py`（前 3 条上下文 + glossary）。
2. **+future context**：前 3 + 后 2。
3. **+constraints**：prompt 明确 max chars/CPS；输出后 QA。
4. **+repair**：只对 QA 失败条二次调用。
5. **+glossary QA**：术语未命中单独修。

通过标准：

- 覆盖率 100%，日语残留 0，回显 0；
- 术语命中率 ≥95%，行长/CPS 违规率比 baseline 降 ≥50%；
- chrF 不低于 baseline −1.0，抽检不低于 baseline；
- 任一项不达标 → 不接主流程，只保留实验脚本。

## 5. 实施顺序（每步可回退）

1. `lib/translation/qa.py`：纯函数 + 单测（日语残留、行长/CPS、术语命中、回显）。
2. `translate_srt.py`：加 `--max-chars`、`--max-cps`、`--qa-report`，不改默认输出。
3. 跑 30 条 baseline，记录指标；再开 constraints 对比。
4. 只对 QA 失败条做一次 repair；再对比。
5. 通过后加 `run_all --translate` 正式阶段（输出到 `translated/`，不覆盖源）。
6. series memory/glossary 跨集：最后做，避免过早复杂化。

## 6. 非目标（本轮不做）

- 不做整集/整系列一次 prompt；
- 不做纯规则翻译；
- 不引入新翻译模型（DeepSeek 已配置）；
- 不用中文对照当金标去调 prompt（只做 guardrail）；
- 不改现有默认翻译输出，除非 ablation 通过。
