# 参考字幕复用（同一部作品的现成译文）

> 适用条件：参考字幕是**同一部作品**的另一个版本，且两者共用素材 —— 总集篇沿用原片剪辑、
> 重制版沿用旧译、特别篇拿原片片段配新旁白。这时参考字幕里有整句现成的人工译文，
> 覆盖我们的机译：人的译文优于机译，专名也随之统一。

## 先判定有没有可复用素材

**分布，不是条数。** 命中频次的形状是判据：

| 形状 | 结论 |
|------|------|
| 连续成段（某几分钟每分钟十几条） | 素材复用 —— 做 |
| 均匀散布（~1 条/分钟，且都是「原来你在这里啊」这类通用短句） | 巧合 —— 别做 |

判据挡得住多数巧合，但**挡不住通用短句**：实测一个非总集篇在 `--min-sim 0.45` 下仍会
接纳 4 条（`这是什么卡？`→`这是什么?`、`喂，等等我啊`→`等等我`）。所以先看分布再决定跑不跑，
跑完还要看采纳清单里是不是通用短句。屏上字也能作证（`ORIGINAL STORY` = 原创剧情，不是总集篇）。

## 三步

```bash
cd "<project-root>"

# 1. 配对（调 LLM 复核，结果有缓存，重跑只补新对）
python "<scripts>/reuse/align.py" -e SP01,SP02 \
  --source-dir temp/ja_raw --target-dir temp/zh_out \
  --reference-dir 字幕 --reference-glob '*.SC.ass' \
  --variants temp/reuse_variants.json --report temp/reuse/report.txt

# 2. 🤖 看报告：命中分布（连续段还是均匀散布）+ 采纳清单里有没有通用短句
#    报告 = temp/reuse/report.txt，或 --out-dir 下的 apply_<集号>.txt

# 3. 改写：dry-run 看判据，再写盘
python "<scripts>/reuse/apply.py" -e SP01 \
  --source-dir temp/ja_raw --target-dir temp/zh_out \
  --reference-dir 字幕 --reference-glob '*.SC.ass' \
  --variants temp/reuse_variants.json                    # dry-run
python "<scripts>/reuse/apply.py" -e SP01 ... --apply     # 写盘（留 <集号>.srt.bak）
```

**改写前先 git commit** —— apply 原地改写译文，没有撤销按钮。

## 配对原理（align.py）

1. **锚点** —— 折叠相似度的单调最长链。复用素材按原片顺序剪辑，对应行也单调，
   锚点夹出的参考区间就是候选窗口。
2. **检索** —— 窗口内按折叠相似度取 top-K（`--sim-floor` 阈值很低，靠复核兜底）。
3. **复核** —— LLM 拿**源语言原句**判断「这条参考译文是不是这句的翻译」。这一步容忍
   ASR 误听与两位译者用词差异，是精确度的来源；通过后按相似度降序贪心去冲突
   （两侧单调、不重复）。

⚠️ `LLM_API_KEY` 是必需的 —— 没有复核就没有配对，脚本直接报错退出（不会静默出 0 条）。
复核结果缓存在 `verify_<集号>.json`，只有拿到明确答复才入缓存，API 失败重跑会重试。

## 采纳判据（apply.py）

| 判据 | 拒绝条件 |
|------|---------|
| R1 短句 | 目标文本 < `--min-len`（默认 4）字 —— 短句极易撞车，换了也没多少信息量 |
| R2 无修订 | 两文本相同 / 只差标点 |
| R3 片段 | 参考文本 < `--ratio`（默认 0.58）× 目标文本 —— 是片段不是同句，换了会丢信息 |
| R4 相似度 | 折叠相似度 < `--min-sim`（默认 0.12） |
| R5 写法 | `never_swap` 里的两种写法互换（昵称 vs 形态名、简称 vs 全称） |
| R6 冲突 | 同一条参考 cue 已被采纳（相似度降序取先者） |

**例外**：折叠后两份文本**完全相同**的（整句只差人名写法）不受 R1/R3 约束 ——
那正是要按参考定译改写的情形（`我是瓦尔古蕾` → `我是瓦尔Q蕾`）。

采纳后并进同集相邻未占用的参考行（参考把一句拆成两三条时，`--adj-gap` / `--max-ext` 控制）。

## 配置：--variants

写法归一与互斥写法。没有它，「只差人名写法」的整句改写识别不出来。

```json
{
  "groups": {
    "女主角": ["瓦尔古蕾", "瓦尔Q蕾", "小瓦尔"]
  },
  "never_swap": [["小瓦尔", "瓦尔古蕾"], ["小瓦尔", "瓦尔Q蕾"]]
}
```

- `groups` —— 同一实体的各种写法。折叠时等价（用于相似度与「只差人名」判定），
  并注入复核 prompt（「A / B / C 指同一个人」）。
- `never_swap` —— 互为误配的两种写法，R5 见到就拒。同一组里可以有不能互换的成员
  （昵称与形态名），**不要**为了省事把它们拆成两组：拆开就丢了「只差人名」这个信号。

## 数据流

| 产物 | 内容 |
|------|------|
| `<out-dir>/matches_<集号>.json` | 配对结果（目标行 → 参考行 + 相似度 + 双方文本） |
| `<out-dir>/verify_<集号>.json` | LLM 复核缓存 `{"目标行:参考行": true/false}` |
| `<out-dir>/apply_<集号>.txt` | 采纳 / 丢弃逐条报告（判据 + 双方文本） |
| `<target-dir>/<集号>.srt.bak` | apply 前的译文（**已存在则不覆盖**，保住最初那份） |

## 坑

- **别在改写过的译文上重跑配对。** R2 会把「完全相同」的对全部丢掉（那时两边已经一样了），
  报告看着像「没有可复用素材」。要重跑就指向备份或原始译文目录。
- **`--styles` 决定取哪些行。** 参考字幕常把 OP/ED、屏字、职员表放在别的 ASS 样式里，
  混进来会污染候选；默认取 `Default,DefaultS`。参考字幕若用别的样式名（如「正文」），
  解析出 0 条 cue —— 脚本会报错叫你改 `--styles`（`--styles ''` 关闭过滤）。
- **改写后与源逐条对数量。** 本流程只换文本不换轴，cue 条数与时间轴必须原样；
  少了一截说明判据之外还有东西动了文件。
- **OP/ED、唱段不要靠本流程。** 那些行按 OP/ED 专项工具（`fix/oped_fixer.py`、
  `fix/oped_fill.py`）走定本，或干脆不碰 —— 用 `--styles` 把它们的样式排除掉。
