# 段 0：前期调研

> 主文档 [SKILL.md](../SKILL.md) 的全流程第一段。开工顺序固定：
> **先查有没有现成字幕 → 再查这作品是什么 → 再把专名写成表**，然后才碰 ASR。
>
> 为什么不能跳：ASR 只能回答「听到什么」，回答不了「正确写法是什么」。
> 没有外部参考时，专名错得系统性且闸门拦不住（`赤道` 是合法日文但不是 `赤胴`）。

## 1. 字幕调研：先问「有没有」

现存字幕决定后面走哪条路，所以要在下载、ASR 之前查：

| 查到的东西 | 走哪条路 | 注意 |
|---|---|---|
| 日文字幕（同一版） | 直接当源语言：校对 + 翻译，不必 ASR | 要核对**版本/集号**是否对得上 |
| 中文字幕（人工） | 只作译名/术语对照，不当源 | 机翻中字（B 站 `ai-zh` 等）不作为依据 |
| 英文字幕 | 可作参考字幕（复用/重打轴），不当源语言 | 见 [reuse-reference-subs.md](reuse-reference-subs.md) |
| 什么都没有 | 走 ASR（[subtitle.md](subtitle.md) 段 2） | 结论要写进项目档案：**没有就是没有**，别拿 AI 字幕凑 |

四类站点各查一遍（语种、覆盖范围不同，别只查一个）。**下表是 2026-10 的实测结论**，
不是「一般来说」：

| 站点 | 语种/范围 | 实测到的检索入口 | 自动化 | 结论 |
|---|---|---|---|---|
| jimaku.cc | ja，动漫 | ① OpenSearch 建议 `https://jimaku.cc/opensearch/suggest?anime=true&query=<词>`：免 key，回 `"<entry_id>: <罗马名>"`；② 条目页 `/entry/<id>` 免登录可见下载链接；③ `/api/entries/search` 要 `Authorization` key（无 key 一律 401，key 在 `/account` 生成） | **半自动** | 脚本能探条目，拿文件清单要 key |
| kitsunekko.net | ja，老番 | 只有全量目录页 `dirlist.php?dir=subtitles%2Fjapanese%2F`（619 KB，一次就是全部片名）；**没有站内搜索**（`&search=` 被忽略、`/search.php` 404）；robots.txt 两行 `User-agent: *` + `Disallow: /` | 人工 | 浏览器里找；尊重 robots，不脚本抓 |
| assrt.net（射手网） | zh 为主 | 存档文档写明 `api.assrt.net/v1/sub/search?token=&q=&cnt=`，JSON，20 次/分；**本机实测整站 TLS 不通** | 人工（需 token） | 先打通网络，再用 token |
| opensubtitles | 多语言 | REST 无 key 一律 403；老站 XML-RPC 通道活着但 `status` 是 `401 Unauthorized`，要先 LogIn 换 token | 人工（需 key） | 申请 key 之后才谈适配 |

> 「待实测」不是省事，是底线：没有实测过的端点和字段不许写进适配器。
> 上表加过的站点，接适配器时按 [acquire.md](acquire.md) 索引站的写法来，并配离线用例
> （喂固定响应，不联网）。

四类站点各查一遍，用脚本生成清单再填结论（**未实测的站点不会拼 URL**，只列入口和
「人工检索」，避免写错的端点浪费时间）：

```bash
python "<scripts-dir>/acquire/subs_search.py" sites      # 站点、语种、自动化程度
python "<scripts-dir>/acquire/subs_search.py" search -q "<日文原名>" # 跑能自动检索的站
python "<scripts-dir>/acquire/subs_search.py" plan -q "<日文原名>" \
  --out "bin/reference_docs/字幕调研.md" --json "data/temp/subs_search.json"
```

> **本机网络坑（实测）**：Clash TUN 开的 fake-IP 会让内置抓取工具把站点解析成
> `198.18.x.x`，报「非公网 IP」直接拒。这时候别以为站点挂了——用
> `pwsh` + `Invoke-WebRequest`/`curl.exe` 走系统代理实测，并拿 `example.com`
> 做对照。写进结论时要区分「站点没有」和「本机没打通」。

**判定与记录**：查到/查不到都要落盘到项目 `bin/reference_docs/`（通常写进
`<作品>_外部参考.md` 的「字幕可用性」一节）：哪些站查了、结果是什么、缺口是什么。
后续任何一步怀疑「名字为什么这么写」时，先回来看这张表。

## 2. 故事背景：这作品是什么

跑 ASR 之前把「作品元信息」定死，否则集号、译名、时代用语全会串。

要查的 A–J（作品与版本、中文通行译名、人物关系、读音、招式、OP/ED、分集副标题、
集号对照、时代用语、上游结构化元数据）与可信度阶梯，全部在
[external-references.md](external-references.md)：**查什么、去哪查、落到哪、常见坑**。

产出：`bin/reference_docs/<作品>_外部参考.md`。这一份是后面所有专名与 OP/ED 定稿的
依据，缺口也要写进去（哪些没查到、用什么替代）。

### 2.1 三层剧情材料，各有各的来处

| 层 | 要什么 | 去哪拿 | 别做什么 |
|---|---|---|---|
| **整体背景** | 舞台（哪个城市/学校/时代）、现实原型、当年的足球/社会语境 | 维基「概要」节、官方/发行方介绍 | 拿搜索摘要当设定 |
| **整体梗概** | 主线怎么起承转合（相遇 → 强敌 → 预选 → 全国 → 收尾） | 维基「あらすじ」全文、台本目录的あらすじ | 按剧情段反推集号（没核实就写集号，后面全是坑） |
| **单集梗概** | 每集到底演了什么 | ① 片尾**次回予告**（旁白把下一集讲一遍，ASR 直接转）；② 日本脚本アーカイブズ等台本库的あらすじ | 照副标题脑补剧情 |

单集梗概的抽法（有 ASR 之后随手就做）：每集末尾 ED 之后到片尾那段是次回予告，
把它按集号收进 `data/reports/单集梗概_次回予告.md`，翻译前扫一眼就知道这几集在讲什么。

> 有原作漫画而动画后半转原创时，**梗概要标出分界**（例：《赤き血のイレブン》第 40 話起
> 改题进原创篇）。原创段没有可靠梗概来源，就按片源实际内容写，不套原作。

### 2.2 定翻译调子：写正面指引，不写禁用清单

调子来自两份东西：**故事背景/梗概**定整体语体，「人物表 + 台词样张」定每个人的口吻。

写法（正面、可用）：

```markdown
**玉井真吾**：短句、喊话，「我／你这家伙」；句尾带狠劲（「我要…」「决不…」「就让你看看」）
**松木天平（教练）**：命令短句，不客套；讲道理直给（「拿出骨气来」）
**旁白（1–18 話）**：半文半白、句子短，像旧新闻片旁白
```

- 每人一行「日文怎么说话 → 中文落点 → 一句例」，比任何形容词都好用；
- 时代词给**译法对照**（`根性 → 骨气/拼劲`），不给「不许译成 XX」的长黑名单；
- 想要强制力就交给工具：`lib/context/style_lint.py` 做确定性检测、`style_patch` 定向改写，
  实测「提示词里加风格块/禁用词表」对成片没有可测收益（[design/style-context.md](design/style-context.md)）。

调子落在 `.meta.json` 的 `style`（`rule` + `voices` + `terms`），并写进外部参考档案的
「语体与翻译口吻」一节，供翻译与人工抽查共用。

## 3. 专名表：从参考落到能用

| 内容 | 落到哪 | 后续谁用 |
|---|---|---|
| 人名/招式/组织 ja→zh | `data/glossaries/<series>.series.json`（扁平映射） | 翻译映射、`nouns/apply_map.py`、文本闸门 |
| 读音（片假名）、`canonical_ja` | 同目录 `.meta.json` 的 `readings` / `canonical_ja` | `namefix` 修 ASR 同音字 |
| OP/ED 逐句原文→译文 | `.meta.json` 的 `op_map`、`fixed_lines` | `fix/oped_fixer.py`、`context_review --mode oped` |
| 集号映射 | 项目 `CLAUDE.md` | 防集号错位 |

写表的两条硬规则：

- 表按 **janome 实际读法**写读音（例：`赤胴` = セキドウ），别按想当然的读法；
- 中文译名先取通行译名（wiki 中文条目优先），自创译名要写进档案说明来源。

## 4. 跑 ASR 前的最后一关：映射完整性

源里会出现的书写形式（含片假名/汉字两种写法）是否都有条目？
没有就在词表里补，或缺一条就记一条缺口——这一关过不了，段 3 的闸门必然漏。

- [ ] `data/glossaries/<series>.series.json` + `.meta.json` 初版就位，读音按 janome；
