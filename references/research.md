# 段 0：前期调研

> 主文档 [SKILL.md](../SKILL.md) 的全流程第一段。开工顺序固定：
> **先查有没有现成字幕 → 再查这作品是什么 → 再把专名写成表**，然后才碰 ASR。
>
> 为什么不能跳：ASR 只能回答「听到什么」，回答不了「正确写法是什么」。
> 没有外部参考时，专名错得系统性且闸门拦不住（`赤道` 是合法日文但不是 `赤胴`）。

## 1. 字幕调研：先问「有没有」

现存字幕决定后面走哪条路，所以要在下载、ASR 之前查：

| 查到的东西 | 走哪条路 | 注意 |
|---|---|---|
| 日文字幕（同一版） | 直接当源语言：校对 + 翻译，不必 ASR | 要核对**版本/集号**是否对得上 |
| 中文字幕（人工） | 只作译名/术语对照，不当源 | 机翻中字（B 站 `ai-zh` 等）不作为依据 |
| 英文字幕 | 可作参考字幕（复用/重打轴），不当源语言 | 见 [reuse-reference-subs.md](reuse-reference-subs.md) |
| 什么都没有 | 走 ASR（[subtitle.md](subtitle.md) 段 2） | 结论要写进项目档案：**没有就是没有**，别拿 AI 字幕凑 |

四类站点各查一遍（语种、覆盖范围不同，别只查一个）：

| 站点 | 语种/范围 | 检索方式 | 自动化 |
|---|---|---|---|
| jimaku.cc | 日文字幕，动漫为主 | 网站检索 + API | 待实测确认接口与鉴权 |
| kitsunekko.net | 日文字幕（老番多） | 站点目录/检索 | 待实测确认目录结构 |
| assrt.net（射手网） | 中文字幕为主 | 网站检索 | 待实测（部分接口要登录 token） |
| opensubtitles.org / .com | 多语言，量大 | REST API（.com） | 待实测（API key 需申请） |

> 「待实测」不是省事，是底线：没有实测过的端点和字段不许写进适配器。
> 查一次的实际形态（URL、返回格式、是否要 key）补进上表，再按
> [acquire.md](acquire.md) 里索引站的写法加适配器（离线用例喂固定响应）。

四类站点各查一遍，用脚本生成清单再填结论（**未实测的站点不会拼 URL**，只列入口和
「人工检索」，避免写错的端点浪费时间）：

```bash
python "<scripts-dir>/acquire/subs_search.py" sites      # 站点、语种、自动化程度
python "<scripts-dir>/acquire/subs_search.py" plan -q "<日文原名>" \
  --out "bin/reference_docs/字幕调研.md" --json "data/temp/subs_search.json"
```

**判定与记录**：查到/查不到都要落盘到项目 `bin/reference_docs/`（通常写进
`<作品>_外部参考.md` 的「字幕可用性」一节）：哪些站查了、结果是什么、缺口是什么。
后续任何一步怀疑「名字为什么这么写」时，先回来看这张表。

## 2. 故事背景：这作品是什么

跑 ASR 之前把「作品元信息」定死，否则集号、译名、时代用语全会串。

要查的 A–J（作品与版本、中文通行译名、人物关系、读音、招式、OP/ED、分集副标题、
集号对照、时代用语、上游结构化元数据）与可信度阶梯，全部在
[external-references.md](external-references.md)：**查什么、去哪查、落到哪、常见坑**。

产出：`bin/reference_docs/<作品>_外部参考.md`。这一份是后面所有专名与 OP/ED 定稿的
依据，缺口也要写进去（哪些没查到、用什么替代）。

## 3. 专名表：从参考落到能用

| 内容 | 落到哪 | 后续谁用 |
|---|---|---|
| 人名/招式/组织 ja→zh | `data/glossaries/<series>.series.json`（扁平映射） | 翻译映射、`nouns/apply_map.py`、文本闸门 |
| 读音（片假名）、`canonical_ja` | 同目录 `.meta.json` 的 `readings` / `canonical_ja` | `namefix` 修 ASR 同音字 |
| OP/ED 逐句原文→译文 | `.meta.json` 的 `op_map`、`fixed_lines` | `fix/oped_fixer.py`、`context_review --mode oped` |
| 集号映射 | 项目 `CLAUDE.md` | 防集号错位 |

写表的两条硬规则：

- 表按 **janome 实际读法**写读音（例：`赤胴` = セキドウ），别按想当然的读法；
- 中文译名先取通行译名（wiki 中文条目优先），自创译名要写进档案说明来源。

## 4. 跑 ASR 前的最后一关：映射完整性

源里会出现的书写形式（含片假名/汉字两种写法）是否都有条目？
没有就在词表里补，或缺一条就记一条缺口——这一关过不了，段 3 的闸门必然漏。

## 5. 完成判据

- [ ] 四类字幕站都查过，结果（有/无/语种/版本）写进档案；
- [ ] `bin/reference_docs/<作品>_外部参考.md` 含作品版本、人物、读音、OP/ED、集号映射；
- [ ] `data/glossaries/<series>.series.json` + `.meta.json` 初版就位，读音按 janome；
- [ ] 缺口清单写清（哪些没查到、用什么替代、后续风险）；
- [ ] 映射完整性检查通过，可以进段 1/段 2。
