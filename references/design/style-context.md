# 语境审查：专名与风格（2026-10-19）

> 两个问题分开处理：
> 1) **专名/术语是否符合这个作品世界** → 需要作品背景，由「语境审查 agent」判；
> 2) **译制风格是否统一** → 先测「在提示词里写风格」到底有没有用，再决定方案。
> 所有结论都来自实验，不按个人偏好拍板。

## 1. 背景档案：只给需要背景的判断用

`lib/context/profile.py` 从已有材料拼出系列档案（年代/类型/人物/固定用语/语体规则），
可选用 LLM 归纳成一段背景说明并缓存（按内容 hash）。

实测（佐武）：归纳出 309 字背景，正确点出「江户町人社会、捕物搭档、奉行所/冈っ引き、
常见场景是长屋/赌场/商铺」，并提示「人名读音多变」。

**它只服务于「这个词/写法在这个世界存不存在」这类问题**，不拿来推导译制风格——
动画里背景和台词脱节很常见（银魂式），用它推风格会自信地错。

## 2. 提示词里写风格，实测没有可测收益

EP051 全 300 条，同一模型/词表/温度，只换附加到 system 的风格块：

| 形态 | 现代语/方言命中 | 语体标准差 | 平均长度比 |
|---|---:|---:|---:|
| 不加 | 10 | 0.098 | 0.751 |
| 关键词（5 个标签） | 9 | 0.096 | 0.719 |
| 散文描述 | 10 | 0.100 | 0.746 |
| 结构化三行 | 10 | 0.101 | 0.724 |
| 显式禁用词表 | 10 | 0.102 | 0.741 |

结论：**在 system prompt 里加风格，四臂无差异**。所以没有给 `translate_srt` 加
`--style` 开关——那会让人以为有效。风格块最多作为「参考」记录在档案里。

## 3. 真正有效的路径：检测 → 定向改写 → 约束校验

### 3.1 确定性检测（`lib/context/style_lint.py`）

三类：现代网络语、北方/东北方言、时代错置概念。词典是用真实数据迭代出来的：

| 误报 | 处理 |
|---|---|
| 「盗贼」含 `贼` → 被当方言 | 移除单字 `贼` |
| 「兄弟」→ 被当网络语 | 移除 `兄弟` |
| 「上头」（= 上级）→ 被当网络语 | 移除 `上头` |
| `整` 在「整理/整齐」 | 加搭配白名单 |

以上都有 decoy 测试（`tests/test_style_spec.py`），precision/recall 断言 ≥0.85。

### 3.2 定向改写 + 校验（`lib/context/style_patch.py`）

对检测出的行请求改写，然后逐条验证：

| 校验 | 拒绝原因（实测） |
|---|---|
| 命中数必须下降 | 15 条（模型把「搞定/离谱」原样留下） |
| 不得引入新命中 | 0 |
| 文言密度涨幅 ≤0.10 | 0（指令里明确「不要把口语改成文言」后没再出现） |
| 长度比 0.7–1.3 | 1 条（1.33） |
| 专名不得丢 | 0 |

52 集实测：

```
检测到 85 条 → 接受 69 条（37 集）→ 命中 70 → 0
拒绝 16 条（15 未改干净 + 1 长度超限）
```

样例：

| 前 | 后 |
|---|---|
| 果然没错。咱俩里头，还是你更会查案。 | 果然没错。我们两个里面，还是你更会查案。 |
| 啥？你要去哪儿？ | 什么？你要去哪里？ |
| 咱们先别急，佐武。 | 我们先别急，佐武。 |

产出是 **patch JSON**（`before/after/reason`），不自动写字幕：
风格改动风险高于专名，先给人看，确认后再落盘。

## 4. 融入整体流程

```
背景档案（profile）──► 语境审查 near：候选变体/写法是否该统一（promote/reject/uncertain）
                          └─ 批准后写 _meta.aliases（备份），再跑 normalize_variants

译文 ──► style_lint（确定性）──► style_patch（约束校验）──► patch JSON（人工确认）
                              └─ LLM style review（sampled，补充语感问题）
```

命令：

```powershell
# 背景 + 近似词审查（只读，--apply-approvals 才写别名表）
python nouns/context_review.py --project <proj> --mode near \
  --candidates <proj>/temp/variants_candidates.json --dry-run

# 采样语体审查（LLM，只出 flags）
python nouns/context_review.py --project <proj> --mode style --sample 3

# 检测 + 定向改写（只出 patch）
python nouns/context_review.py --project <proj> --mode style-fix
```

## 5. 测试

| 文件 | 锁什么 |
|---|---|
| `tests/test_context_review.py` | profile 结构/缓存、near 决策的枚举与越界、approvals 幂等与备份、style flag 过滤 |
| `tests/test_style_spec.py` | 原文特征（古语/粗口/敬语）、关键词生成、hint 长度、词典 decoy、P/R 下限 |
| `tests/test_style_patch.py` | 改写校验（残留/文言超标/长度/专名）、分段请求、缺 ID、坏 JSON |
